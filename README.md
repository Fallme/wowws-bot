# 战舰世界自动战斗控制台

驾驶更新：预设舰船已启用 Q/E 敌舰优先和带舵机延迟的避山预测。
地图边长、舵效和转弯半径需按实船校准，详见 [驾驶调研与校准](docs/navigation_research.md)。

这是一个在 Windows 本地运行的实验工具。用户在网页控制台选择舰船、战斗模式和停止条件后，程序会自动完成启动游戏、港口检查、选择舰船、加入战斗、战斗控制、结算以及下一局。

> 最简单的使用方式：下载项目，解压，然后双击 `start_project.bat`。不需要手动输入 Python 命令。

## 一、安装前准备

预设设置新增 **OCR 识别设备**：可选 CPU 或 NVIDIA 显卡，选择会在浏览器中保存，下次启动任务生效。显卡模式先验证真实推理；缺少组件时自动在项目虚拟环境安装 CUDA/cuDNN 依赖，安装或验证失败则记录原因并回退 CPU。首次安装需要联网，可能耗时较长；程序不会安装或更新系统显卡驱动。运行中修改选项不会中断当前对局。

实时日志包含 OCR 毫秒耗时、实际执行后端，以及按键派发耗时（包含按住时间，不代表游戏已响应）。未实现的副炮锁定不再发送定时 X 按键。

只需要准备：

- Windows 10 或 Windows 11；
- 64 位 Python 3.11，安装时勾选 **Add Python to PATH**；
- Steam 版或 WG Game Center 版《战舰世界》；
- 首次安装依赖时能够联网。

建议把项目解压到普通磁盘目录，例如：

```text
E:\wowws_bot\
```

不要直接在压缩包内运行，也不建议放在桌面、OneDrive 同步目录或包含特殊符号的深层目录中。

## 二、下载与一键启动

### 普通用户：下载 ZIP

1. 在 GitHub 项目页面点击 **Code → Download ZIP**。
2. 将 ZIP 完整解压到一个新文件夹。
3. 双击项目根目录中的 `start_project.bat`。

> 项目根目录只保留这一个启动入口。它会自动创建 `.venv`、检查并修复基础依赖、启动本地控制台、等待 8899 端口就绪，再打开浏览器。启动过程写入 `data/startup.log`，失败时窗口会停留并显示日志位置。

第一次运行会自动创建项目专用环境、安装基础运行依赖，然后打开：

```text
http://127.0.0.1:8899/
```

首次启动通常需要几分钟。以后仍然只双击 `start_project.bat`；控制台已经运行时，它只会重新打开网页，不会重复启动服务。如果依赖不完整，也会自动修复基础依赖。

控制台默认使用普通权限启动。只有检测到正在运行的游戏确实使用管理员权限、普通输入会被 Windows 拦截时，点击“开始自动战斗”才会弹出一次“用户账户控制”确认并自动续接启动。控制台只监听本机 `127.0.0.1`。

### 熟悉 Git 的用户

```powershell
git clone https://github.com/Fallme/wowws-bot.git
cd wowws-bot
.\start_project.bat
```

以后更新：

```powershell
git pull --ff-only
.\start_project.bat
```

## 三、开始自动战斗

1. 登录 Steam 或 WG Game Center；游戏可以提前打开，也可以让控制台自动启动。
2. 在“游戏客户端”中选择 **Steam** 或 **WG 版（直接启动）**。控制台会从注册表、客户端配置和常见安装目录自动检索路径，不需要手动填写。
3. 选择“联合作战”或“非对称作战”。
4. 选择预设舰船；自定义舰船时，名称必须与港口显示完全一致，并填写副炮射程。
5. 设置停止条件：完整局数、运行时长或不限。
6. 按需勾选“快速战斗”或“完成后关闭游戏”。
7. 点击 **开始自动战斗**。

客户端按钮下会显示检测到的路径；如果当前选择的客户端尚未找到，启动时会在实时日志中给出明确原因。WG Game Center 模式不会自动回退到 Steam，避免启动错误账号或错误区服。

WG 版通过命令行直接运行 `bin/<当前服务器构建>/bin64/WorldOfWarships64.exe`，不打开启动器页面或依赖按钮识别。每次启动都会从当前区服的 CSIS 查询服务器版本，采用 WG 客户端相同的多版本选择依据：已经下载的新版本可能尚未在该区服生效，不能只看 `game_info.xml` 的 installed 或最新目录。服务器切换后自动选择对应游戏本体；缺少所需版本时明确报错，需要先完成游戏更新。网络查询失败时只使用同安装、同区服的服务器版本缓存，并在启动日志中说明。

工作目录使用游戏安装根目录，沿用客户端启动时的账号区服、画质、UI 和按键配置；同时读取 `app_type.xml` 传入对应 `--apptype` 参数。控制台版本信息只读取本地缓存，实际启动时重新查询。只有真实游戏窗口出现才确认启动完成；游戏若要求重新登录，仍需在游戏中完成登录。

本项目不调用启动器或点击启动按钮。WG 游戏本体自带的平台 SDK 在后台组件未运行时仍可能自动初始化 WG 后台进程，并要求本体重新启动；此时等待当前进程对应日志确认初始化完成，且这份游戏安装处于可启动状态，再重试同一本体一次。等待最长 30 秒，点击终止可取消；后台超时或本体再次退出时明确报错，不再无限等待窗口。旧会话日志、其他游戏安装和单纯的客户端进程存在不能触发重试。

WG 版只直接启动游戏本体。旧环境变量 `WOWS_WGC_LAUNCH_MODE=launcher` 不再切换到启动器；`WOWS_WGC_GAME_EXE` / `WOWS_GAME_EXE` 只用于定位安装目录，不能锁定旧版或预下载版 EXE。即使更新移除了指定的旧版文件，也会从同一安装目录解析当前区服版本。

启动后，同一个主按钮会根据状态自动变成：

```text
开始自动战斗 → 暂停 → 继续
```

右侧的 **终止任务** 会结束本次计划，终止后不能继续；临时离开请使用“暂停”。

## 四、暂停与人工操作

- 单纯移动或点击鼠标不会触发自动暂停。
- 按键盘或切换到其他窗口会暂停新的自动操作。
- 只要用户仍在持续操作，程序不会强行切回游戏。
- 停止操作并连续静默 5 秒后，程序才会尝试返回游戏，并从当前画面重新识别流程。
- 持续操作达到 20 秒后会锁定暂停；如果用户仍在其他窗口，需要回到网页点击 **继续**，回到游戏窗口并静默后也会自动解除。
- 在网页主动点击“暂停”后，也必须点击“继续”才会恢复。

切屏、键盘介入、自动恢复和手动继续都会显示在实时日志中。恢复时不会沿用暂停前的旧按钮或旧页面，而是重新判断当前处于匹配/加载、战斗、结算还是港口。暂停期间暂时找不到游戏窗口也不会终止任务；点击继续后会等待窗口重新出现，再从当前阶段接续。

已经点击“加入战斗”、进入加载或见到战斗 HUD 后，本局会一直锁定到连续确认结算页。期间即使切屏恢复时画面短暂误判为港口，也不会进入选船；只有连续确认结算后才计入一次局数。若暂停期间从已确认的结算页回港或进入下一局，旧局仍只计一次，收益无法读取时会明确记为“未识别”。

## 五、控制台怎么看

- **当前状态**：任务现在处于启动、准备、战斗、结算、回港还是暂停阶段。
- **地图区域**：开局打开 M 地图并用五帧投票锁定本局山体和占领点；自身位置、白色航向箭头和敌舰位置由右下角小地图持续更新。白箭头偶发漏一帧时会短时沿用最近可靠位置。
- **定位容错**：黄色射程圈仅作辅助；没有黄色圈时，唯一且形状明确的白色箭头仍可定位。箭头暂时不可识别不会阻塞已经确认的战斗入局；加载页保护和航点点击前的定位检查仍保留。
- **自动驾驶**：航点点击后等待左下角绿色“自动驾驶”文字确认，同时用实际位移和航速验证；控制台显示的是实际下发的 Q/E 或“原生自动舵”，不再猜绿色 HUD。
- **舰船状态**：生命、火灾、进水、航速、舵位以及 R/其他消耗品状态。
- **画面适配**：按游戏客户区截图尺寸处理分辨率与长宽比，左下速度盘/生命状态、底部按键排和实际地图网格分别定位 UI 大小与位置。目标标签跟随实际敌舰标记，港口/弹窗按钮使用文字实际坐标，结算收益通过标题和资源列定位。M 地图识别与航点点击共享实际四角和透视映射；截图尺寸变化或几何证据不足时重新识别，不猜航点。每帧日志保存 `hud_layout` 的比例、区域和锚点来源，方便根据截图修正新布局。
- **R 损管保护**：确认火灾/进水时尝试 R；8 秒内掉最大血量 8% 且下一次新鲜血量读数复核仍处于低血量时，或 24 秒内至少 3 次下降、累计掉最大血量 2% 时，也尝试 R。持续下降允许夹杂相同读数；回血、读数中断、沉没或暂停后重新累计，缓存帧不会充当复核。沿用 80 秒尝试间隔；输入失败保留受损证据，间隔 2 秒再试。发送 R 仅代表尝试，不代表游戏已经启用损管。阈值与时间窗口可在 `config/ship.yaml` 中调整。
- **近距离鱼雷**：包括自定义舰船在内，先用两次新截图确认实际“3 号键位＋鱼雷图标”。默认在 0.25～6 km 内尝试（含 6 km 边界），已知舰船同时受射程限制。切换鱼雷后识别装填绿色扇区、当前发射方向和白色提前量扇区，以有限相对鼠标移动调整；连续两帧确认方向对齐才发送一次鼠标左键单击。缺少白线时，敌舰靠近准星且目标唯一才尝试一次 X 锁定。装填中、目标丢失、暂停、沉没、菜单或分辨率变化会取消本次发射。随后重新确认战斗画面并尝试恢复 2 号主炮，暂停时留待继续后恢复。装填倒计时作为发射反馈，未读到时只记录输入已派发。单次瞄准总限时默认 30 秒，每次输入要求对应截图不超过 4 秒；距离使用连续新截图复核，避免异步旧值误取消正在接近的目标。近距离阈值、最小距离和瞄准限时在 `config/ship.yaml` 调整；自定义舰船不继承波美拉尼亚的鱼雷射程。瞄准与发射前后的截图及判定数据保存到 `E:/aimemo/docs/screenshots/wows_torpedoes/`，每局最多保留 60 张。
- **鱼雷目标搜索**：主视野没有敌舰时，小地图连续三帧确认 6 km 内的同一敌舰，可在重新验证存活血量、当前玩家箭头、红色目标和实际 3 号鱼雷武器后有限移动镜头。每次最多 8 步/30 秒、冷却 10 秒，每局最多 24 步；暂停恢复保留预算。看到敌舰标记就停止，重新读取真实距离；搜索不改变自动航线或发射武器。相机角度未标定，有限搜索不能保证发现所有遮挡目标。前后截图和取消原因保存在上述目录的 `target_acquisition` 子目录。
- **实时日志**：建议排查问题时先看最后几行；不再显示单独的“问题处理后重试”按钮。
- **本组累计**：完整战斗的银币、舰船经验、全局经验、局数和累计用时。

## 六、两种运行方式

### 完整对局

正常等待战斗结束，读取结算数据，然后优先点击“继续战斗”。如果结算页不能直接继续，会自动回港，再从港口入口开始下一局。

完整结算页的胜负通过“胜利/失败”标题文字识别，并经至少两次读数确认；无法确认时保留为未知，不猜测败局。后续未知读数不会覆盖已入库的胜负，日志中会记录确认结果。

收益读取每次重新采集当前游戏画面，不复用战斗阶段的缓存截图，避免结算页被旧图反复判为战斗。资源数值需要多帧共识，最多重试三组、每组六帧；若仍未识别但当前结算页已确认，会保存诊断截图、将收益记为“未识别”并继续计划，不累计不可靠数字。切屏暂停不消耗重试额度；页面发生变化时保留本局证据，重新识别后恢复流程。

### 快速战斗

勾选后，单局达到 5 分钟、确认沉没或离开战斗 HUD 时会退出本局并继续下一局。快速战斗计入计划局数，但不统计收益和胜负。

“完成后关闭游戏”只会在整组计划正常完成时生效；暂停、手动终止或异常不会关闭游戏。

## 七、常见问题

### 双击后没有打开网页

先等待首次启动完成，也可以手动打开 `http://127.0.0.1:8899/`。若启动窗口提示找不到 Python，请安装 64 位 Python 3.11 后重新双击；启动失败详情在 `data/startup.log`。

### 安装依赖失败

检查网络后再次运行 `start_project.bat`。脚本会复用已经安装成功的内容。NVIDIA OCR 组件安装失败时会自动使用 CPU，不影响基本运行。

### 显示“游戏画面不可用”

确认游戏没有最小化，并等待日志重新绑定游戏窗口。一般无需管理员权限；仅当游戏自身以管理员权限运行时，开始任务会提示一次 UAC。若拒绝 UAC，任务不会启动，也不会发送无效指令。不要同时启动多个控制台。

### 想更新程序

使用 Git 的用户执行 `git pull --ff-only`；下载 ZIP 的用户重新下载并解压到新文件夹。个人运行数据默认保存在项目内的 `data/` 和 `runtime/`，这些目录不会上传到 Git。

## 八、数据与隐私

以下内容只保存在本机，并已排除在 Git 之外：

```text
data/                          控制台设置、任务历史和运行状态
runtime/screenshots/runs/      最近完整一局的全画面截图、events.jsonl、round.log
runtime/screenshots/manual/    手动截图
runtime/ocr_reports/           OCR 离线测试报告
training_assets/user_captures/ 用户反馈截图
```

每局确认完成后会封存该局证据并删除更早的局，只保留最近完整一局；进行中的局不会中途清理。需要释放全部空间时，可在任务停止后使用控制台的“清理截图”。

阻塞诊断另存于 `E:/aimemo/docs/screenshots/wows_blockages/`，覆盖未知遮挡、战斗菜单、收益读取、普通回港、快速回港和结算导航。每个阻塞序列最多保留 60 帧，包含近期缓存画面、恢复动作前后截图和最终状态；`observations.jsonl` 记录识别状态、动作、次数及时间，便于后续回放分析。收益读取序列 `result_rewards_*` 额外记录当前截图、HUD 判定、资源投票和最终共识。阻塞目录独立于每局截图，不随旧局封存清理，也不受控制台“清理截图”影响。

未知页面只有在顶部角落确认 `Esc ×`、`Esc 关闭` 或 `Esc 返回` 等关闭提示后，才允许累计最多三次 Esc；每次按键前都重新截图复核，提示消失即停止。没有提示或存在比赛计时、血量等实时战斗证据时只保留截图观察。沉没后的观战画面仍属于战斗，底部 `Esc 离开战斗` 不作为关闭遮挡的依据。已知战斗菜单/离场框也须重新截图并核对中心文字；快速战斗主动离场继续使用其专门流程。暂停或停止时暂停截图和操作。
