# 闭环重构架构

## 设计原则

1. 指令被驱动接受，不等于被游戏接受。
2. 单帧视觉结果不能触发高风险动作。
3. 无法证明当前画面有效时，控制必须回中。
4. 状态、输入和反馈必须分别记录，日志不能混用“派发”和“执行成功”。

## 运行状态

```text
blocked -> preflight -> preparing -> battle/armed -> battle/verified
                                    \-> failed/tripped
```

- `blocked`：缺少校准或分辨率不一致。
- `preflight`：确认窗口、画面和初始界面。
- `armed`：已派发航行指令，等待位移证据。
- `verified`：小地图玩家位置达到最小位移阈值。
- `tripped`：画面失效、HUD 丢失或指令无反馈，控制已回中。

## 核心边界

- `core/gamepad.py` 只负责派发，不宣称游戏已执行。
- `core/calibration.py` 保存人工确认的实机动作映射。
- `core/frame_guard.py` 检测空帧、黑屏和长时间不变化的画面。
- `core/feedback.py` 使用玩家小地图位置验证航行响应。
- `core/vision.py` 负责视觉事实，不直接决定游戏动作。
- `core/ocr.py` 在后台读取目标标签公里距离，并按目标轨迹做时序融合。
- `core/events.py` 把识别、决策和反馈写成可回放的结构化事件。
- `bot.py` 组合观察和策略，并在任何证据不足时停止。

## 航行闭环

```text
敌舰标签 OCR 实距 + 小地图每格 5 km + 玩家箭头中心/航向
  -> 中央占领点/地图中心航向 + 当前目标距离/相对方位
  -> 前向航行走廊的岛屿距离/左右净空
  -> 紧急避岛 > 鱼雷规避 > 航路避岛 > 站点推进
  -> 点外全速 > 圈外敌人小幅航向修正 > 点内减速留守
  -> 手柄派发 + 小地图位移反馈
```

岛屿识别只保留有填充面积的低饱和度地形块，并排除细网格线和射程环。航向走廊只检查舰艏前方，左右各投射一条候选通道，选择净空更大的一侧转舵；连续两帧均确认地形后才触发动作。真实距离需要同一目标两次一致 OCR 才能进入公里策略；OCR 失效时按小地图 10×10 网格、每格 5 km 换算。低血量和近敌不再单独触发掉头。

## 可观测性与回放

控制面板从运行状态读取目标公里值、距离来源、OCR 置信度、是否位于占领点、移动状态和决策理由。每局 `events.jsonl` 同时记录距离观测与每个控制 tick；`tools/replay_events.py` 可检查点外全速、点内减速与紧急避岛约束。

## 保留资产边界

历史截图、标注和模型保存在 `training_assets/`，不被运行程序自动加载。只有纳入明确测试或经过重新训练验证的资源，才可以进入 `assets/` 或运行配置。
