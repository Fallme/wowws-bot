# 路线与收益的学习式调优方案

状态：设计稿，未安装学习框架，未启动训练或实战试验。

## 1. 学习对象

采用“固定驾驶控制器 + 可学习的路线选择 + 批量参数搜索 + 对照验收”。第一版每局只选择一次方案，局内依据既定规则接管，局后更新。不要同时训练图像识别、船舶动力学和路线，否则收益变化无法归因。

三层职责：

1. 感知层：固定现有 OCR，输出船位、航向、敌舰、陆地、置信度与数据年龄。
2. 控制层：现有 HelmModel、YawMotion、地形避障、Q/E 五档控制及人工暂停。碰撞约束、失去定位后的保护、用户接管不参与收益优化。
3. 策略层：选择路线族、目标规则、原生驾驶转 Q/E 的条件和有限参数。学习器只能选择通过约束检查的方案。

不能跨地图复用绝对像素航点；同一种路线族要按本局归一化地图、可通行区域、出生位置实例化。未知地图先走保守基线，不把未验证地图模板作为真实地形。

## 2. 第一版候选方案

| 方案 | 开局 | 接敌和接管 |
| --- | --- | --- |
| baseline | 冻结当前项目版本 | 当前参数，作为持续对照 |
| early_contact | 原生开局，采用朝敌方的可达航点 | 敌舰位置连续确认且可安全接近时较早接管 |
| clear_corridor | 优先选地形净空较大的通道 | 按预计安全航行时间选择敌舰，减少绕山 |

所有方案使用同一驾驶控制器、同一识别器和火控配置。避免一边改路线一边改开火频率。只有在此阶段稳定之后，才研究局内多次路线重规划的序列决策。

## 3. 优化目标与防止奖励误导

第一期默认主目标为单位运行时间的结算银币；若未来能可靠采集服务费用等扣款，再改为净银币，并改变目标版本号。当前结果页 credits 不可直接命名为净利润。

主指标：

`credits_per_hour = 3600 * sum(有效结算银币) / sum(对局周期秒数)`

必须是总额除以总时长，不是逐局比值的平均。周期从开始匹配到可开始下一局，包含加载、战斗、结算和项目自身故障恢复；单独记录用户主动暂停时间，给出包含与排除暂停的两套统计。快速回港不能提前终止其对应收益的归属周期。

其他指标单独展示，不盲目相加：舰船经验/小时、副炮范围首次进入时间、有效接敌时长、绕行比、碰撞次数、触边时间、脱困时长、控制指令反转频率、人工介入率、结算采集成功率。

路线的局内诊断可用：

`诊断分 = 安全接近目标的进展 - 碰撞/触边持续时间 - 无效停滞时间 - 频繁换向代价`

各项按固定基线尺度归一化，权重版本化。它只解释路线问题，不替代结算主目标。靠近敌舰不是收益证据；有射程也不等于无遮挡或已产生副炮伤害。没有攻击观测时，“几何进入副炮范围”和“副炮有效输出”必须分开。

碰撞、人工介入、异常终止是约束，不能让高银币抵消失控。主动送死、提前退出、无限拖延等待也不能通过缩短分母、遗漏失败样本得到高分。

## 4. 数据合同

现有基础：`core/events.py` 提供 JSONL 事件；`control_server.py` 中 `runs`、`battle_history`、`resource_entries` 保存运行和收益；`core/results.py` 提供识别状态、原文和各字段置信度。现有字段不代表已经具备完整训练样本。

新增数据以 `battle_id` 关联，兼容当前 `(run_id, round_no)`；结果页、港口卡片和后补识别必须去重。

| 数据集 | 必要字段 |
| --- | --- |
| battle_context | 地图及识别可信度、出生位置/方向、船型与配置、模式、游戏版本、经济加成、高级账号状态、时段 |
| policy_assignment | policy_id、配置 hash、代码版本及未提交代码快照 hash、随机种子、可选方案集合、实际选择概率、选择时可见上下文 |
| navigation_trace | 单调时钟、船位/航向/航速及置信度、数据年龄、舵指令、估计实际舵位/角速度、目标、原生或 Q/E 状态、岸线净空、接管原因 |
| battle_outcome | 起止时间、收益字段及 recognized/confidence/raw_text、结果来源、终止原因、碰撞/触边证据、人工介入、收益缺失原因 |
| experiment_registry | 目标版本、基线版本、候选版本、训练/验证划分、晋级规则、开始时间、汇总及回滚原因 |

连续状态建议每 1 秒记录一次，换舵、接管、碰撞疑似、识别失败按事件即时记录；采样周期是建议值，不强制改变现有控制频率。关键帧保存在 `E:/aimemo/docs/screenshots/` 对应子目录，其余数据进入项目 `data/tuning/`。

收益缺失用 null，不用零。保留失败及干预对局，不只收集胜利。主报告同时展示全体分配对局的时长/可靠性、有效收益样本和缺失比例；缺失较多或候选与基线缺失明显不平衡时禁止晋级，进行缺失收益敏感性分析，不能直接删除失败局后宣称改善。

经济加成未知时只进入诊断集，或在相同且固定的配置下做试验。资源手动补录和煤/钢等非逐局收益不混入路线训练目标。

## 5. 离线调参

先校准物理模型，再优化策略：舵响应、速度尺度、转弯半径和残余角速度属于系统辨识参数，应用新鲜航迹拟合，不能通过“银币高不高”间接猜测。

第一轮只搜索三个实际控制参数，范围为试验建议而非已验证最优值：

| 参数 | 建议范围 | 约束 |
| --- | --- | --- |
| opening_autopilot_minimum_seconds | 20–60 秒 | 保留独立的起步宽限和停滞确认 |
| rudder_minimum_hold_seconds | 2–5 秒 | 紧急避障仍可越过普通保持时间 |
| qe_prediction_horizon_seconds | 30–60 秒 | 地图/船位可靠时才启用规划 |

安全净空第一阶段固定当前值，不让搜索主动压低。然后独立比较路线族，不把全部维度一次展开。

可使用 Optuna TPE 做有预算的参数搜索：先少量粗筛，再对优胜候选增加重复评估。[Optuna 官方 TPE 文档](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html)

旧截图回放只能验证感知和“同一已发生状态下会选择什么动作”；换一条路线后，后续位置、敌情和收益都会改变。因此不能拿旧录像给新路线算真实胜率、真实碰撞率或收益。仿真可筛掉明显撞山/越界轨迹，但只产生代理指标，必须在模型参数扰动和未见地图上测试；不得把仿真收益作为正式晋级证据。

## 6. 在线选择范式

数据少时使用分层随机 A/B；稳定积累后采用上下文多臂老虎机。上下文是开局已知的地图、出生侧、船型等，动作是整局路线方案，反馈是局后收益和约束结果。这符合“只观察被选择动作的奖励”的情形。[Vowpal Wabbit 官方说明](https://vowpalwabbit.org/docs/vowpal_wabbit/python/latest/tutorials/python_Contextual_bandits_and_Vowpal_Wabbit.html)

第一版开局分配之后保持该策略版本不变；不要把每一次 Q/E 都当作独立老虎机动作，因为它们对未来有长期影响。未来需要局内学习时，单独设计带状态转移和延迟奖励的序列策略。

只有通过离线检查的候选可探索，探索率设上限。每次记录候选集合和真实选择概率，包含筛选后的重新归一化概率。旧日志若没有选择概率，不能假装能进行可靠的 IPS/DR 反事实评估；候选没有历史覆盖也不能离线证明它更优。

## 7. 对照和晋级

按船型、模式、经济配置固定试验；地图与出生侧作为分层或协变量。小样本分组不要细到每组只剩一两局。按局随机分配基线/候选，在相近时段交错运行，避免“昨天基线、今天候选”的时段偏差。

第一轮先补采约 20–30 局基线用于估计方差和数据完整性；这只是启动预算，不保证统计显著。之后比较一个候选与基线，根据基线方差、预定最低有意义提升（例如 5%）与置信要求确定所需样本。样本不足时结论为继续观察。

晋级同时要求：

1. 实战收益/小时的提升达到预定幅度，且按对局或运行批次聚类重采样的差值置信区间支持改善。
2. 碰撞、触边、人工介入和异常终止满足预设绝对上限及相对基线非劣界限；必须看不确定性，而不是“这几局没撞”就判安全。
3. 采集成功率达到预先规定门槛，缺失敏感性分析不推翻结论。
4. 在独立验证批次或未参与挑选的对局中仍然有效。

先冻结判定规则和评估时点；多候选择优、反复偷看结果都会造成乐观偏差。探索数据用于筛选，最后保留单独验证批次，或使用预先设计的序贯检验。不能每次刚涨一点就自动晋级。

## 8. 部署闭环

`记录基线 → 校验数据 → 离线筛选 → 固定候选 → 随机实战对照 → 晋级/继续观察/淘汰 → 小比例发布 → 回滚监测`

维护一个只读 champion 配置和候选配置。调优器生成候选文件，不直接覆盖 `config/ship.yaml`。晋级在下一局边界生效；发生解析错误、连续感知失效、持续触岸或需要人工接管时，当前局进入既有保护逻辑，后续局恢复 champion，记录原因。不得在转弯中直接更换动力学参数。

## 9. 建议实现顺序

1. 数据阶段：增加策略标识、上下文、逐局时长、缺失语义和回放校验；输出每局一行的数据表。
2. 评估阶段：实现固定基线报告、分层收益/小时、可靠性统计和训练/验证隔离。
3. 试验阶段：实现单候选分层随机 A/B 与候选配置加载，保留每局选择概率。
4. 学习阶段：加入有限预算的参数搜索，再加入上下文路线选择；保持独立最终验证集。

第一期验收重点是可复现、能解释改进、能回滚。只有数据与收益链路可信后才值得投入更复杂的强化学习。
